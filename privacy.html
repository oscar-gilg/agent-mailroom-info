Oscar Agent Mailroom · Privacy

Privacy and data use

Oscar Agent Mailroom is personal software operated by Oscar Gilg. Its purpose is to let the owner give instructions to Claude Code and Codex by email and receive their results.

Data accessed and stored

With the account owner’s OAuth consent, the application reads messages from a dedicated Gmail account, sends email from that account, and updates message labels and read status. It requests the Gmail modify permission for these functions.

The VM stores raw incoming messages, including their headers and MIME content, along with routing information, sender and recipient addresses, subjects, message identifiers, processing status, error details, session identifiers, and generated orchestrator responses. Raw messages can contain attachments; the current implementation does not extract inbound attachments for agents. Outgoing reports can include files selected by the owner or their agents.

Processing and sharing

Authenticated instructions are forwarded to the selected local agent session. General requests go to a Claude orchestrator with earlier authenticated owner messages from the same thread. These agents may send message content and task context to Anthropic or OpenAI under the owner’s account settings and the providers’ terms. Google processes the mailbox and email delivery.

The mailroom sends results only to its configured owner. It does not sell Google user data, use it for advertising, or intentionally submit it to train a general-purpose AI model. Instructions can request additional actions or sharing through the connected agents; those actions remain subject to the agents’ permissions.

Retention and security

Credentials and runtime data are kept outside the source repository in private files on the owner’s VM. OAuth tokens and the mailroom database use owner-only file permissions. Access to Google uses HTTPS. Local administrators or anyone with access to the owner’s operating-system account may be able to access these files.

The mailroom has no automatic retention deadline. Messages and records remain until the owner removes them. Copies in Gmail, agent transcripts, backups, and provider systems have their own retention settings.

Control and deletion

The owner can stop the mailroom service and revoke its Google account access at Google Account connections. Revocation stops future authorized API access; it does not delete existing copies. The owner can remove local mailroom state and credentials, delete messages in Gmail, and manage agent histories and provider retention separately.

Questions about this personal application can be directed to the support email shown on its Google consent screen.
