Oscar Agent Mailroom · Privacy

Privacy and data use

Oscar Agent Mailroom is personal software operated by Oscar Gilg. Its purpose is to let the owner give instructions to Claude Code and Codex by email and receive their results.

Data accessed and stored

The application reads and sends messages through a dedicated email account and updates processing labels. AgentMail connections use a private API key. Optional Gmail connections use the account owner’s OAuth consent and request the Gmail modify permission for these functions.

The VM stores raw incoming messages, including their headers and MIME content, along with routing information, sender and recipient addresses, subjects, message identifiers, processing status, error details, session identifiers, and generated orchestrator responses. Raw messages can contain attachments; the current implementation does not extract inbound attachments for agents. Outgoing reports can include files selected by the owner or their agents.

Processing and sharing

Authenticated instructions are forwarded to the selected local agent session. General requests go to a Claude orchestrator with earlier authenticated owner messages from the same thread. These agents may send message content and task context to Anthropic or OpenAI under the owner’s account settings and the providers’ terms. AgentMail processes the connected AgentMail mailbox and delivery. Google processes Gmail mailboxes and Google OAuth. Email also passes through the recipient’s provider.

The mailroom sends results only to its configured owner. It does not sell Google user data, use it for advertising, or intentionally submit it to train a general-purpose AI model. Instructions can request additional actions or sharing through the connected agents; those actions remain subject to the agents’ permissions.

Retention and security

Credentials and runtime data are kept outside the source repository in private files on the owner’s VM. API credentials, OAuth tokens, and the mailroom database use owner-only file permissions. Provider API access uses HTTPS. Local administrators or anyone with access to the owner’s operating-system account may be able to access these files.

The mailroom has no automatic retention deadline. Messages and records remain until the owner removes them. Copies in the email provider, agent transcripts, backups, and provider systems have their own retention settings.

Control and deletion

The owner can stop the mailroom service and revoke the AgentMail API key in the AgentMail console, or revoke a Gmail connection at Google Account connections. Revocation stops future authorized API access; it does not delete existing copies. The owner can remove local mailroom state and credentials, delete messages in the email provider, and manage agent histories and provider retention separately.

Questions about this personal application can be directed to the support email shown on its Google consent screen.
